## Post

Back in 2003 our "security testing" was a guy called Dave.

Dave would sit at the end of the office, type random rubbish into every form field, and occasionally shout "it's broken again." We loved Dave. Dave found quite a lot of bugs.

Dave did not find 81.

That's how many previously unknown high-severity Firefox vulnerabilities OpenAI says its new GPT-6 Cyber model turned up. Plus hundreds more in the Linux kernel. Not guessed at. Actually validated, with working exploits.

Honestly, that number stopped me in my tracks.

Firefox isn't some weekend side project. It's had brilliant people looking at it for over twenty years. And there were still 81 serious holes sitting there, quietly waiting.

Now here's the bit I keep thinking about.

The same tool that helps the good folks find those bugs is going to be pointed at your code by someone a lot less friendly. OpenAI is gating access for now. But "for now" has a habit of not lasting very long in this industry.

So what do we do? Basically, the same things we should've been doing all along.

Write the tests. Keep your dependencies tight. Patch quickly. Treat a security bug report like a gift, not an insult.

The tools have changed a lot since Dave and his keyboard.

The fundamentals really haven't.

Curious what others think. Is AI bug hunting going to make our software safer, or just make the race faster?
